## 本轮方法

各候选需在代码修改前补齐问题证据、所有者、改动边界和验收场景。优先处理高频重复计算、无界内存、重复 IO、取消后继续工作的路径，不为低频小操作引入复杂缓存。

- 会话/协议：扫描剩余高频归约、目录、流式与缓存生命周期，同时 review 第一轮的顺序和失效规则。
- 文件/服务：扫描文件搜索、读取、监听、Git 与进程查询，核对取消、并发和缓存隔离。
- 前端：扫描其余渲染、预览和首屏依赖，保留懒加载和 UI 局部状态边界。

## 候选、实现与验收

第二轮共完成八项改动，详细所有者、时序与验收分别记录于 `performance-round2-conversation.md`、`performance-round2-io.md`、`performance-round2-frontend.md`。

| 项目                   | 结果                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------- |
| 导航摘要缓存           | 复用未变化的历史轮次；1,000 轮尾部更新时，历史正文重复读取 1,000 → 0 次                 |
| 单行增量与结构共享定位 | 复用有序 rowId 二分定位；10,000 行 Store 的 rowId 访问 29,999 → 少于 100 次             |
| 目录失效与请求代际     | 终态、rewind、snapshot、首次查询中的 guide 不再提交过期摘要；新代际等待旧请求收口后查询 |
| 高亮缓存               | 完整源码键避免误命中，100 次同键并发 tokenize 100 → 1 次；LRU 限制项数、字符和 token    |
| DOCX 解析              | 链接回调变化不再重新解析文档，字节/路径变化仍重新解析，旧任务禁止提交                   |
| 文件索引规则读取       | 缓存命中只检查指纹；23 次查询/分块调用的规则内容读取 23 → 1 次                          |
| 文件监听               | 10,000 个不同路径的解析 10,000 → 2 次，待发送路径最多保存 1 个                          |
| 旧 Host 搜索兼容       | 有界复核至多 80 条返回候选，排除目录及非多词 AND 匹配，保留原返回顺序                   |

这些数字来自合成回归中的访问/调用计数，不是整机延迟、实际堆字节或包体缩减。不可变数组复制仍存在，不能据二分定位宣称整个更新已变为 O(log N)。
