# 第三轮前端性能：文件树批量删除与改动筛选

## 证据与范围

- `workspace-file-tree/model.ts` 的 `addDeletedGitStatusRowsToWorkspaceFileTree` 对每一条 Git deleted 状态扫描当前目录 children，然后复制和排序完整数组。同目录批量删除时，后续删除还会重复扫描前面新增的虚拟行；排序和复制也随删除数重复。
- 保持文件树显示、目录优先顺序、文件名 localeCompare 排序及相同名称的稳定顺序，不调整交互、协议、服务请求或状态来源。
- 目录 Git 聚合在“仅改动”筛选中对全部已加载目录逐个扫描完整 Git Map，未受列表虚拟化限制。筛选完成后列表与吸顶只为可见行生成圆点状态，属于不同工作量边界。

## 所有者与规则

1. Git service 仍拥有 Git 状态，`useWorkspaceFileTreeRows` 仍拥有当前树的派生投影。本函数只在一次调用内建立局部索引，不保留跨调用状态。
2. 只为已有 children 的目录补充 deleted 文件。workspace 之外、根路径、未加载目录以及非 deleted 状态全部沿用原先忽略规则。
3. 同一受影响目录只构建一次规范化路径 Set，检查原始行及本批已添加行。路径规范化继续替换斜杠并去除末尾分隔符，保持大小写敏感；不新增平台或远端身份推断。
4. 每个真正添加了虚拟行的目录只复制一次 children、只在本批完成后排序一次；保留既有行对象。输入 Map、数组和节点不得被修改，未改变目录保留数组引用；整批无新增行时返回原 Map。
5. 虚拟行的 name、depth、type 与 path 使用原先公开 helper 和契约。无持久化迁移、异步时序、网络重试或新状态所有者。
6. “仅改动”筛选在一次调用内根据 Git 路径建立祖先目录 Set，每个 Git 路径只访问一次；按现有规范化后的斜杠边界逐级登记，保持大小写敏感、严格 descendant 关系。文件自身非 ignored 状态仍直接判定为改动，目录仅有 ignored descendant 仍沿用原先保留规则。
7. 该 Set 仅在 changedOnly 为 true 时建立，没有跨刷新或跨 workspace 缓存；关闭筛选沿用原数组引用。搜索过滤顺序和父子保留规则保持不变。

## 验收

- 先建立回归并确认旧实现的工作量断言失败，再实施批量合并。覆盖空输入/非删除、workspace 外及未加载目录、已有同路径、不同分隔符、大小写不同路径、同名不同 type 的目录优先排序、相同名称稳定排序、嵌套目录深度和输入不可变。
- 以 1,000 条同目录 deleted 文件为合成场景，统计 localeCompare 调用次数。结果保持排序正确，比较次数从反复排序的约 500,000 次下降到一次排序的数量级；不据此宣称整机耗时或真实仓库的固定加速倍数。
- 执行目标 Vitest、定向 lint 和格式检查；主代理统一根 typecheck、lint、架构检查与最终 review。不提交、推送或构建。
- 目录筛选先建立工作量回归：1,000 个目录与 1,000 个 Git 路径，完整 Map entry 访问次数从 1,000,000 降到 1,000；用现有逐目录公开查询作参考核对 POSIX/Windows、混合分隔符、末尾分隔符、相似前缀、大小写、根目录、ignored descendant 与搜索组合结果。

## 实施与验证

- 已实现每目录一次局部路径索引、一次 children 复制及一次批量排序。没有新增跨调用缓存，现有 hook 与 UI 入口保持不变。
- 回归先失败：1,000 个同目录删除文件的比较次数为 499,500，超过 12,000 的工作量上限；修复后在同一 Node 24.14.0 环境通过该上限。该计数描述合成输入上的排序工作，不是整机延迟。
- 新增 6 项回归与既有 `sidebarFileTreePath.test.ts` 19 项，共 25 项通过。定向 lint 0 warning/error；架构检查 0 基线、0 新增违规。
- 自 review 与主代理独立 review 核对局部索引与已有路径归一化等价、输入与未改变目录引用保留、同名稳定排序和 Windows 深度规则，未发现剩余可操作问题。
- 目录圆点渲染的边界：`WorkspaceFileTree` 的 `visibleRows` 用 useMemo，changed-only 全树过滤不随单纯滚动重复；列表使用虚拟化、overscan 12，渲染聚合只覆盖视口及缓冲行中的目录，另加吸顶祖先目录。行装饰的 helper 没有 memo，仍可能随渲染重复，但本轮没有测得其真实调用规模与耗时，因此没有新增跨组件缓存。
- 补充复核确认 changed-only 单次过滤仍有全树重复工作：1,000 个目录与 1,000 个变更路径，旧实现 Map 访问 1,000,000 次，局部祖先 Set 实现为 1,000 次。新增 4 项回归先有 1 项失败，修复后与前述删除、路径回归合计 29 项通过；没有修改列表圆点聚合或其 UI 接口。
