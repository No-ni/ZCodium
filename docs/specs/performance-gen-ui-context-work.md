# 性能扫描：Gen UI 模型上下文的增量序列化

## 范围与基线

保留开工时所有本地改动，不提交、推送、打包或操作现用业务数据。freshness 通过：当前 perf/linear-hotpaths 相对 origin/main ahead 1 / behind 0，无远端跟踪分支。架构初检 violations / baseline / new 为 0 / 0 / 0。已读取 gen-ui-protocol 受控上下文、module、contract、示例、CONTRACT.md 与既有测试。

验证使用预装 Node 24.18.0，mise.toml 固定 24.14.0；未找到 mise 或已安装的固定版本，不修改本机环境，明确报告版本差异。

## 已确认问题

`buildGenUiModelContext` 的实际调用方是 SessionPane 的提交上下文读取。原实现排序并截取至多 100 条状态，逐项校验完整 state；每加入一项，再复制、序列化、UTF-8 编码整个已选前缀，最后再次序列化完整结果。即使返回上下文限制为 64 KiB，重复处理也随已选项数量增加，最多重复访问 5,150 个输出项而不是 100 项。

## 设计与不变量

- 改动只在 managed gen-ui-protocol 的纯 domain 契约实现内，不新增接口、依赖、缓存、异步任务或可变业务状态所有者。
- 持久化 state 仍由现有 Host 所有者提供，本函数只在一次调用内派生字符串。页面、workspace identity/session 隔离、owner/lease、Desktop continuous 与 mobile replayable 的链路均不变。
- 保留 path 的 localeCompare 稳定排序，先截取最多 100 条、再验证和过滤的顺序。不把无效或 modelContent=null 的项替换成第 101 项。
- 完整 state（包括 privateContent）仍按原 schema 校验、JSON 克隆并限制为 16 KiB。只有 modelContent 进入上下文；false、0、空字符串仍有效。
- 每个候选输出对象只序列化一次，UTF-8 数量按两个方括号、各序列化对象以及对象之间的 ASCII 逗号精确累加。超过 64 KiB 的首项仍停止扫描，而不是跳过后再挑选小项。
- 最终 JSON 数组由已序列化的片段拼接，字段顺序、字符串转义与原 JSON.stringify 数组一致。`<` 的替换仍在预算检查后进行：不借性能任务改变现有预算定义或包装文本。
- 新文本和状态每次重新校验，不复用前次结果。输入数组、条目和 state 均不修改。

## 验收

先添加测试并在旧实现执行，记录正确性通过、工作预算断言失败；再实施修复。

1. 保存原算法为仅测试使用的参考函数，新旧完整输出字节相等；固定种子混合有效/无效状态、排序重复路径、Unicode、JSON 转义、空值与私有字段。
2. 精确覆盖 64 KiB 边界和超出 1 字节、UTF-8 多字节与孤立代理项；原预算在转义 `<` 前计算的行为不变。
3. 验证排序后截取 100 条、无效项过滤、首个超限项停止、输入不可变及私有内容不输出。
4. 直接计数输出项序列化工作：100 条小状态由 5,150 项访问降为 100 项。耗时只记录合成输入观测，不作为 CI 硬断言，不宣称应用整体提速。
5. 执行已有 Gen UI 协议/持久化/前端派生测试、根 typecheck、lint、架构复检与本轮格式检查。此为纯函数等价优化，不改 UI/DOM 交互，无新增应用 E2E 场景。

## 结果

- 修改前 11 项（本轮 5 项 + 既有 6 项）正确性 10 通过，仅工作预算失败，实测 5,150 次输出项访问。修改后 11/11 通过，工作量为 100 次。
- 160 份固定种子混合状态的完整文本与旧算法相等；精确 UTF-8 边界、孤立代理项、排序前截取、私有字段验证和输入冻结均通过。
- 已纳入 106 文件 / 737 项整合回归，全部通过；根 typecheck、lint 和架构检查通过，详见本轮总报告 `performance-scan-verified-improvements.md`。
- 未进行真实应用端到端或整机 CPU/内存测量，没有计时收益宣称。
