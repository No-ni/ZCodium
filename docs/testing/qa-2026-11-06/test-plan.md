## 验证规则

1. 以当前实际可见入口为范围；已删除的官方登录、云服务、遥测等不作为待恢复功能。
2. 菜单盘点、源码/契约审查、自动化检查、桌面交互和真机/联网验证分别记录，不能互相替代。
3. 每个清单项记录入口、前置条件、动作、预期结果、实际结果、证据、状态。只有本轮断言执行且通过才标记通过。
4. 功能问题先复现再登记；区分已确认产品 Bug、测试基础设施缺陷、环境阻塞和待验证假设。
5. 交互缺陷留存逐步截图及视频；无法产生 UI 证据时明确说明，不虚构操作或结论。
6. 所有测试数据、HOME、profile、缓存、临时目录及日志均限制在 `C:/vibecoding/zcodium`，运行前验证真实路径和重解析点，子进程继承隔离环境。不使用真实用户目录、真实 `.zcodium`、系统临时目录或项目外远程测试目标。
7. 不自动发送消息、提交代码、安装发布包、上传诊断、购买或使用真实 API Key；需要外部设备、密钥或服务的路径标明未执行条件。
8. 必需执行 `corepack pnpm typecheck`、`corepack pnpm lint`，保存真实退出码与失败摘要。

## 工作分解

- 菜单/功能盘点：`feature-inventory.md`。
- 质量检查与安全确定性测试：`validation.md`、`logs/validation-*`。
- 桌面/Web 隔离运行和现有 E2E 可执行性：`e2e-environment.md`。
- 本轮测试结论与覆盖状态：`test-report.md`。
- 已确认缺陷、复现及后续验收：`bug-report.md`。

优先覆盖启动、主导航、项目与任务、输入与会话、文件/Git/终端/预览、设置、插件/自动化、帮助以及平台与远程边界。详细清单在盘点后补充。

## 验收

交付完整入口清单、实际执行结果和证据索引、可复现 Bug 条目与未执行原因。环境阻塞的功能明确标记阻塞，不能宣称每个菜单均完成真机测试。
