## 已有测试体系与主要缺口

当前根 `package.json` 提供 `typecheck`、`lint`、`test:engineering`、`test:engineering:affected`、`test:architecture`、`db:schema:check`、`audit:conversation-session-coverage` 等入口。UI 包没有统一 `test` script；桌面 E2E 实际命令是 `corepack pnpm --filter @zcode/desktop test:e2e`（Windows shards），serial 为 `test:e2e:serial`，覆盖入口为 `test:e2e:all:coverage`。这些入口是否适合本轮执行，由测试执行者先审查写入范围及当前产物。清单编写者未执行它们。

可作为用例索引的当前文档：`docs/conversation-session-case-catalog.md`、`docs/conversation-session-validation-matrix.md`、`docs/plugin-mcp-skill-case-catalog.md`、`docs/plugin-management-lifecycle-case-catalog.md`、`docs/usage-stats-e2e-case-catalog.md`、`docs/bots-e2e-case-catalog.md`、`docs/site/sites-e2e-case-catalog.md`。历史文档可能描述被剥离的官方功能，最终边界仍以当前装配和 `docs/specs/maintenance-model.md` 为准。

必须补足或单列的验收缺口：

1. **菜单全覆盖**：很多 E2E 只证明某个行为，不能证明菜单每项都被点击。需要以本表 ID 写运行记录，明确 PASS/FAIL/BLOCKED/NOT-RUN/N/A。
2. **本 fork 历史用例失配**：`help-client-config.test.ts`、`feedback-upload-privacy.test.ts`、`plugin-lifecycle-telemetry.test.ts`、官方 CDN/套餐/更新/分享测试保留了上游命名或假设。先核对源码/fixture，不能把期望官方云行为失败直接记产品缺陷。
3. **待审 E2E**：项目管理、远控恢复、Windows reveal/日志导出、Office security、大量 SSH/同步 cases 仍在 `manual-review/pending`，覆盖报告必须显式标出。
4. **平台真机**：当前 Windows 环境无法替代 macOS 原生菜单/dmg/权限/屏幕录制/系统主题；手机真实网络/触控、Windows DPI/托盘/Chrome 系统导入也需单列证据。
5. **设置细粒度**：proxy/CA、唤醒、数据目录、白板/文件活动图、所有技能/命令表单动作缺专用可见 E2E 或需要更精确 catalog 对应，不能由 `settings-ui-polish` 统一带过。
6. **网络和外部动作**：Provider 请求使用 mock；Git 用本树隔离 repo/bare remote；MCP 用本树 fixture；SSH/relay/Bot/插件下载缺环境时标 BLOCKED，不读取或修改真实个人目录、Key、Chrome profile，不向外部发消息/建 issue/发布站点。
7. **结果真实性**：本文件是范围与待测点清单。没有运行截图/日志/具体测试输出的条目均不能在最终报告中写“通过”或“完成真机验收”。
