# 长回复终态：共享代码按钮提示与隔离实测

本轮确认并减少了终态重挂时的控件开销。240 个代码围栏原先创建 480 个独立 Radix Tooltip Root；现在每个 MessageResponse 只管理一个活动提示，按钮保持挂载，提示在悬停或键盘聚焦时创建。生产模式的 7 次前后对照中，终态提交中位数降低约 31%；另外 3 次真实键盘排队试验中，终态输入回显延迟降低约 48%，历史重挂期间降低约 59%。仍观察到约 50～60ms 的长任务，不能宣称卡顿已全部消除。

## 改动与所有者

`CodeBlockTooltipScope` 是提示目标的唯一所有者，记录 hover、keyboard focus 和 Escape 抑制状态；Context 只提供稳定的事件接口，不广播活动目标。480 个按钮不再各自登记 Radix trigger/ref 状态。仅活动提示使用原 ControlHintTooltip，复用其样式、浮层和 Escape 行为。真实按钮的 aria-describedby 关联 Radix 实际生成的描述节点，关闭时只移除自己的 ID。

相对本轮开工快照，`message.tsx` 只增加作用域导入和包裹，净增 3 行；`code-block.tsx` 只替换复制、折行和 Mermaid 预览按钮的提示封装，净增 0 行；新增提示所有者文件 385 行。复制/折行/预览的按钮与 click handler 保留，Streamdown parser/mode、完成态 remend 防护、live-tail 迁移和 RPC 均未修改。作用域外的代码块沿用原独立提示。

设计、目标身份清理规则与事件图见 [spec](../../specs/performance-terminal-render.md)。架构检查将这部分 UI 识别为现有未托管区域，本轮没有新增架构模块、跨层导入或业务状态。

## 生产模式对照

原始样本见 [evidence.json](evidence.json)。Node 24.14.0、Corepack pnpm、Windows 无头 Edge 155.0.4283.45，1280×900，真实 MessageResponse / Shiki / 完整 UI CSS，合成正文 34,122 字符、240 个 TypeScript 围栏。Vite 只生成临时网页夹具；没有构建桌面应用或安装包。

每个变体先运行 1 个预热页面，再用 7 个新页面交替 before/after、after/before 采样；每页依次完成 streaming→static 和随后历史重挂。before 加载器只替换本轮开工保存的两个展示入口，其他依赖、CSS 和夹具均相同；脚本断言两个文件均命中，实际各命中 1 次。[source-comparison.patch](source-comparison.patch) 记录精确差异，[sources.json](sources.json) 记录两份输入的 SHA-256。

| 指标                     | 修改前中位数 / p95 | 修改后中位数 / p95 |
| ------------------------ | -----------------: | -----------------: |
| 终态提交                 |      73.2 / 79.7ms |      50.2 / 55.7ms |
| 终态区间脚本 CPU         |    148.4 / 158.8ms |     96.9 / 103.3ms |
| 终态区间长任务总时长     |        163 / 173ms |        112 / 114ms |
| 终态首个可见代码高亮 DOM |    237.8 / 249.0ms |    183.4 / 188.6ms |
| 历史重挂提交             |      67.5 / 70.2ms |      45.8 / 46.7ms |
| 历史区间脚本 CPU         |    112.5 / 119.2ms |      58.9 / 61.3ms |
| 历史区间长任务总时长     |        103 / 108ms |          50 / 51ms |

修改后的终态提交范围为 48.1～55.7ms，修改前为 71.1～79.7ms。终态区间从原先一次 105～117ms 长任务和一次 54～60ms 长任务，变为两次约 53～61ms 工作。历史重挂原先每次有 102～108ms 长任务，修改后 7 页中 4 页记录到 50～51ms，另外 3 页未超过 Long Task 的 50ms 阈值。

提交时间是动作发起到父组件 layout effect，包含解析、React render 与 commit；不等同于完整绘制。长任务从动作发起观察到首个高亮 DOM 出现及其后两帧完成，脚本 CPU 是对应 CDP 区间累计指标，包含测量和高亮工作。高亮时间只表示 DOM 已出现。JSON 另存的 twoRafMs 从动作之前开始计时，可能早于异步工作结束，不用它证明整段内容已绘制。7 个样本的 nearest-rank p95 等于该组最大值，不能当成稳定尾延迟。

每个新页面有独立 JS realm，终态首次高亮可能包含 Shiki 冷初始化；随后历史重挂复用同页已初始化的高亮器。本组结果说明同机组件的相对改善，不能直接等同于打包后的 Electron 或日常热态整机性能。

## 真实键盘排队

使用另外 6 个独立页面，每个变体 3 页。真实 CDP Enter 触发终态，紧接着发送 x；Alt+Enter 触发历史重挂后同样输入 x。两个 keydown 同时从 Node 发出并带同一生成时间戳，时间戳与浏览器 event.timeStamp 的偏差实测不超过 0.1ms。所有样本通过校验，脚本断言全部显示正确的 x 回显且没有浏览器异常。历史阶段先等待首次高亮 DOM 和后续帧，避免与冷初始化混测。

| 输入回显延迟   | 修改前中位数 / p95 | 修改后中位数 / p95 |
| -------------- | -----------------: | -----------------: |
| 终态期间 x     |    116.2 / 117.1ms |      60.6 / 61.0ms |
| 历史重挂期间 x |    129.9 / 133.0ms |      53.2 / 54.3ms |

回显延迟从浏览器 keydown 原始时间到输入组件 layout effect 计算，不把 Node/CDP 返回耗时作为结果。它仍是受控合成场景，3 样本 p95 也是最大值。Event Timing 只保留达到 16ms 的条目，没有条目不能理解成零延迟。

- 7 个相关单测文件、38 个用例通过，覆盖代码片段生命周期、缓存边界、查找、文件链接及完成态标题/列表/引用/表格/数学和字面量 `./src/**/*`。
- 真实浏览器代码片段回归通过：240 围栏、手机/桌面宽度、复制/折行、中文/制表符/emoji、明暗主题、原生/会话查找、Range 节点稳定、离屏释放、streaming→static、历史重挂，以及高亮预算、未知语言、缺少 IntersectionObserver 和迟到回调。
- 共享提示回归通过：按钮 DOM 身份、hover 切换、迟到 leave、Tab/焦点、Escape、原 ARIA ID 保留与清理、滚动、resize、目标卸载。测试驱动修正了“Escape 后离开其他 hover 目标会错误恢复焦点提示”的边界。
- Mermaid 实际渲染、预览按钮启用、共享提示及 ARIA、点击打开含图形 SVG 的 dialog，以及提示退出后的 Escape 关闭均通过。dialog 自己的提示仍保留独立所有者。
- 查找的另外 4 项浏览器测试通过。
- 根级 `corepack pnpm typecheck`、`corepack pnpm lint`、`architecture:check --changed` 通过；架构 baseline/new/total 均为 0。新增和修改文件执行 Oxfmt 检查。

测试使用独立无头浏览器、临时 profile、临时网页输出和缓存，只允许夹具同源请求；没有调用应用内模型 API，没有启动业务服务端、安装应用或真实 Agent，没有修改业务数据和配置，没有提交、推送或触发 Actions。测量脚本的 finally 清理自身资源。

测量时源码快照目录尚未清理；其中仅有两个合成测试使用的源码副本和 manifest，没有安装产物或业务数据。此处省略具体本机临时路径。

## 剩余边界

本轮减少了控件批量创建造成的同步工作。完成态仍会做完整 Markdown 解析和 React 子树重建，首次可见代码高亮仍在主线程初始化/分词。现有高亮入口有可见性、20,000 字符和结果 token 预算，以及有限缓存；这些边界不能保证单次冷初始化低于 50ms。进一步减少这部分阻塞需要针对解析或高亮执行边界继续取证，不能靠增加延迟、缓存或关闭完整 Markdown 语义来宣称解决。

当前交互验证使用真实产品按钮与 mouse/keyboard；自定义调用方的 preventDefault、回调 ref 转发及 touch pointerEnter 未单独构造浏览器场景。没有用 SSR 伪造事件结果，也没有测试安装后的 Electron、真实会话或手机远控链路。

同目录的三个 profile JSON 是更早的定位采样：`profile-before.json` 使用开发态 React，另两个使用生产 React 与 Vite 开发服务；tooltip probe 只在加载器中移除提示树。它们支持选择优化目标，不能和本报告生产 bundle 的耗时混用，也不是最终收益数据。
