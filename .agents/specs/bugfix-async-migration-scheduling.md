# 已确认 Bug 修复

## 产品规则

- 数据目录迁移完成后，目标目录必须包含源目录中所有可迁移文件；目标已存在的同名文件不能静默保留旧内容。
- 自定义 weekly schedule 的下一次运行必须按周一到周日的实际日期顺序计算。周日用值 `0` 表示，但它位于周一之后，不是当前周的第一项。
- workspace 文件索引使用有界并发扫描。并发上限是 8，根目录发现子目录后必须继续填充空闲 worker。
- Git 分支列表和提交辅助状态只能属于发起请求时的 workspace。workspace 变化后，旧请求的结果必须丢弃。
- Bot 保存、绑定码和扫码注册结果只能更新发起请求时的 Bot；用户切换 Bot 后，旧响应不得改变当前选择或覆盖当前 Bot 的临时状态。
- 模型目录批量添加的成功结果必须从当前弹窗选择中移除；部分失败重试只能提交仍未成功的模型。
- 数据目录浏览产生的是草稿。浏览完成后草稿必须保留，保存失败后也必须允许用户重新选择并保存。

## 状态所有者与边界

- `settingService`/`paths` 负责迁移文件语义；UI `DataBaseDirControl` 只负责草稿和保存状态。
- `automationCron` 负责纯日历计算；UI 只生成 `scheduleRule`。
- `fileService` 负责索引扫描队列，结果排序仍是唯一输出顺序。
- `useGitBranchSwitcher` 负责 workspace 代次；`BotsDialog` 负责 selected Bot 代次和绑定/注册临时状态；目录弹窗负责当前可选项。

## 异步事件顺序

```text
请求开始(owner key) -> workspace/Bot/弹窗身份变化 -> 请求完成
                                      └─ key 不匹配：丢弃响应，不写状态
```

保存或迁移的成功边界是实际服务调用完成；失败只更新错误状态，不把用户草稿替换回旧事实。

## 验收

1. 目标数据目录已有同名文件时，迁移后内容与源文件一致。
2. 自定义 weekly `[0, 1]` 从周一上午计算时，下一次先命中当天周一，而不是周日。
3. 多目录扫描时同时进行的 `readdir` 数量可达到但不超过 8。
4. workspace 或 selected Bot 在请求期间变化时，旧结果不改变当前界面；同一 owner 的新请求仍可正常完成。
5. 模型目录部分成功后，重试不会再次调用已经成功的 model id。
6. 数据目录浏览在 saved/error 状态后仍保留新草稿。
7. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check -- --changed` 和新增针对性测试通过。
