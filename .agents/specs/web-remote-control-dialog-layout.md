# 手机远控弹窗：双栏展示与 fork 滚动边界

## 产品规则

- 视口宽度至少 768 CSS px 时，同屏左侧显示连接方式、二维码与状态操作，右侧显示 Bot 渠道和管理入口；窄屏按扫码在前、Bot 在后的单列顺序展示，不再使用标签页隐藏另一条路径。
- 弹窗保留左右至少 16px 边距，二维码等比缩放且保持正方形；长文案、最大界面字号与低矮窗口不能产生横向溢出或裁掉底部操作。
- 标题和关闭按钮固定在正文滚动区外。正文继续复用细窄的 `ScrollArea`，只在滚动时显示滚动条，不能恢复穿过关闭按钮的通顶原生滚动条。
- 保留纯变暗遮罩、不叠加背景模糊、关闭按钮 no-drag 与启用控件的手指指针。打开任何 Bot 配置入口时仍收起外层远控弹窗，避免两个模糊遮罩同时渲染。
- 两列使用真实标题命名的语义区域；关闭按钮复用 `common.close`。中英文说明两条访问路径；渠道可用性以当前 `botsUi.ts` 的 `BOT_PROVIDERS` 与 BotsDialog 为准，AstrBot、微信、飞书、Lark、Telegram 五个入口均已开放，不能继续显示未开放文案。
- 扫码命令的禁用状态始终读取当前 `useWebRemoteControl.busy`；刷新确认已打开后若 Host 进入忙碌，确认按钮也必须禁用，不得绕过外层刷新按钮并发发出命令。忙碌解除后可确认一次，取消仍不提交。

## 所有者与接口

这是展示改动，不新增远控业务状态、查询任务清单或新的连接写入路径。现有窗口级 Main 运行时与 Host 保持连接、attachment、owner/lease 和会话权威；`useWebRemoteControl` 仍是投影与命令入口。任务清单同步继续由现有窗口级同步所有者维护，不迁回弹窗。

```text
点击扫码操作 → useWebRemoteControl → IPlatformService → 现有窗口远控运行时
                    ↑ 状态投影 ←──────────────────────────┘
点击 Bot 入口 → 记录本地 entryProvider → 关闭外层弹窗 → 现有 BotsDialog
桌面 continuous ── 现有 Host 实时流
手机 replayable ── 现有快照 / 缺口恢复（均不改动）
```

弹窗本地状态仅有 Bot 配置开关/选中渠道和刷新确认开关。宽窄切换不重建二维码 Hook，不中断已配对连接；关闭/重新打开后正文自然回到顶部，不保存跨次打开的滚动深度。

## 验收场景与证据

1. 真实组件、真实 Tailwind、真实中英词典在 1200/768/390/320px 与 Zai 明暗主题下呈现正确双栏/单列，二维码正方形，内容无横向溢出。
2. 低矮窗口和最大界面字号下，滚动能抵达两列末尾；关闭按钮保持可见，滚动轨道只在正文内，遮罩计算样式不含背景模糊。
3. 复制只调用已有 copy；刷新取消不调命令、确认只调一次；确认期间 busy 从 false→true 时禁止点击提交，true→false 后恢复；busy/idle/失败显示保持现有规则；连接设置仍经既有设置 Hook 保存。
4. 五个 Bot 入口与总管理保留 workspacePath/identity 和 entryProvider 透传，打开配置后外层远控内容卸载，不存在叠加的远控遮罩；关闭配置可再次打开远控。
5. 不在弹窗新增任务订阅/清单加载；窗口级同步回归与 existing desktop-continuous/mobile replayable 回归不变。
6. 测试夹具仅监听 loopback、使用虚构状态，无用户配置、凭据或外部请求。目标自动测试入口为 `node scripts/ci/web-remote-control-dialog-smoke.mjs`，另用受控浏览器查看实际渲染和操作。

## 同步边界

只吸收上游双栏展示，不采用上游弹窗内清单同步、整窗原生滚动或保留双弹层的实现。不恢复 Rust 产品、Linux 资源、第二发行产品或工作流自动触发；现有 Windows EXE/macOS DMG、`.zcodium` 与自有更新源边界保持不变。
