# Source workspace alias

One Node owner coordinates a `.zcodium` root. Preview/getters are read-only. Source identity and verified legacy routes come from an injected authenticated authority, never from a client-selected path. Confirmation binds source generation, candidate snapshot and plan hash.

A stopped-writer lease is required for execution and restore and must cover every writer of both databases and all declared config roots under the same dataRoot, not just the selected workspace. `writersStopped: true` is explicit user acknowledgement only; it never substitutes for that lease. Source ID/generation, verified keys and the CLI project ID are frozen and revalidated before each COMMIT or rename. Separate Host SQLite, CLI SQLite and hashed config roots use verified immutable published backups and durable before/after phase and rename intents; alias publishes last. Retry never reselects canonical or erases divergent later writes. Restore requires unchanged schema, exact owned postimage and durable evidence for any already-restored image; it is not a DDL downgrade.

All filesystem reads reject links (including root ancestors and file hardlinks), nested data roots and changed file identity. SQLite inspection uses an explicit committed snapshot and never repairs recovery sidecars. Native Node readOnly can mutate even an existing WAL SHM, so the current Node adapter refuses WAL and unknown/nonzero rollback-journal headers before opening SQLite; a real zero-write consistent storage snapshot port is required for WAL support. Only an at-least-eight-byte zero-magic cold journal is accepted for read-only inspection, with file identity revalidation; OS-temp full-file manifests verified that this does not write storage. Explicit retry/restore may recover only its own uncommitted rollback transaction, under the real root-wide lease and unchanged authority/root generation, verified backups and durable intent matching both database/journal identities and complete byte hashes. It never deletes a journal or treats an empty transaction as proof of cleanup. Pure Node path APIs do not provide dirfd-level protection against a hostile concurrent rename; the real root-wide lease and a trusted data-directory owner are preconditions.

Browser consumers use contract/index only. Node composition uses node and supplies explicit roots and authority; no default user-data scan or migration runs on construction.

## Workspace admission inspection

`ISourceWorkspaceInspectionService` is a separate read-only RPC descriptor. Source Core supplies its authenticated installation identity and actual declared history roots. Its strict three-state result contains no data-root paths or content. The Node implementation only observes safe filesystem presence, never opens SQLite, starts Agent, uses initializing business getters, claims sessions or writes aliases/approval. Any database/sidecar, config-history root or alias-control material conservatively blocks as `history-present`; permission, scope/boundary uncertainty and detected changes block as `unavailable`. A clear observation admits only this logical attachment, not migration or all-writer exclusion. Equal endpoint observations are not a native interval proof. Existing daemon startup/maintenance can create databases and therefore overblock; this adapter does not stop or fence those independent writers. Host workspace preparation must invoke it on every initial connect, reuse and bind, and retire stale generation results before scoped publication.

## Zero-write WAL snapshot boundary

The narrow committed-snapshot port is a trusted backend capability, not a client-provided flag. It owns the complete original DB/WAL/SHM tuple, its root/path identity, byte hashes and change generations, the isolated copy and cleanup, and calls a scoped consumer only after proving a committed image. WAL salts/checksums and the last complete commit frame/database size must be verified; uncommitted tails never become business rows. Original files are never opened by SQLite. Only the isolated OS-temp copy may create SHM or recover, without discarding WAL or changing the original journal mode.

A native read barrier, or atomic full-tuple capture plus a monotonic source-change epoch, must prove consistency and no changes throughout capture. Equal endpoint hashes/stat alone do not prove that interval. Any observed change rejects as `snapshot-stale` and requires a new preview; missing proof rejects as `snapshot-unproven`. The pure Node adapter must fail closed when file APIs cannot establish that proof; schema-valid evidence is not a substitute for the native capability. No Host/UI/Server, writer lease or existing WAL write/recovery path is wired by this task.

`createNodeCommittedSnapshotPort` performs bounded-position asynchronous read-only observations of the original tuple, checks root/file identities and presence twice, closes all held handles and always refuses to publish an image because it has no native interval proof. A locked Windows SHM read is incomplete evidence, not permission to call a test-only mapping tool. Capture observers are trusted Node fixture hooks only. Cleanup failures retain the primary safe error code. This negative safety implementation neither creates a SQLite clone nor calls the consumer; it does not enable the existing WAL inspection or execution paths.
