# Window project directory

The optional `windowProjectDirectory` is one complete capability group on the controlling Window Host. `window-project` exposes that Host's existing `IProjectService`; `window-remote-projects` exposes its existing `IRemoteProjectService`. The Host's project storage owns the local project tree and retained remote entries. Window tabs, Main, relay and Mobile do not create a second membership owner. Reads and mutations use this same group; `window-project-changes` only exposes capability readiness and project invalidation.

`projectService.readTree({ includeDeleted: true, includeDeletedTasks: true })` returns the existing `ProjectTree`; `remoteProjectService.readDirectory()` returns the existing `RemoteProjectDirectory` (`hosts` and `entries`). `projectService.readDirectory()` is a different operation: Host filesystem browsing for project selection, returning `path` and `entries`. Its response must never be parsed as `WindowProjectDirectorySnapshot`. The latter remains the still-used, strict Main-to-Host tab projection wire type; it is not a directory service response. No client synthesizes its generation, workspaces or tasks from filesystem entries.

All three channels are exposed on the existing attachment. File, model, task, and runtime services remain scoped to that attachment; no broadcast write, claim, secret, or configuration API is added. Missing capability keeps the legacy compatibility path and does not count as an available Window directory. An advertised capability whose version check fails must reject readiness rather than silently selecting Source directory services. Mobile installs the optional proxies on its pre-open ChannelClient without replacing its reader or replay sequence, and rejects a capability response from a superseded bridge before publishing readiness.

Mobile's shared Root uses the same accessor instance and `ProjectDirectoryProvider` as the other Web layout. There is no Mobile-only directory read/merge facade or retained directory state. The provider's existing request sequence, service identity and subscription cleanup fence late tree/remote responses; bridge generation fences transport preparation. The real directory responses retain their existing public contracts and errors. The obsolete Mobile tab-snapshot presentation and its retired App tests are removed rather than adapted into another directory projection.
